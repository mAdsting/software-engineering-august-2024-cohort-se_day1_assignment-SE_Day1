Compare and contrast the Waterfall and Agile methodologies. Provide examples of scenarios where each would be appropriate.
The Waterfall methodology follows a linear and sequential approach, where each phase is completed before moving to the next. It has low flexibility, making changes difficult once a phase is finished, and customer feedback comes late, after the product is developed. Testing is done at the end of the process. In contrast, the Agile methodology is iterative and incremental, allowing for high flexibility and adapting to changes. Customer feedback is continuous and incorporated in each sprint, with testing done after every iteration. Waterfall is best suited for projects with fixed requirements, such as construction and regulated industries, while Agile is ideal for dynamic projects, like software development and startups.

Discuss the importance of Integrated Development Environments (IDEs) and Version Control Systems (VCS) in the software development process. Give examples of each.
IDEs, such as Visual Studio Code (VS Code), provide an all-in-one platform for writing, compiling, debugging, and testing code. They improve productivity by offering features like syntax highlighting, code completion, automated formatting, and debugging tools, making development faster and reducing errors.

Version Control Systems (VCS), like Git, help teams manage code changes over time. They enable collaboration, track modifications, allow branching and merging for parallel development, and support error recovery by rolling back to previous versions when needed.

Together, IDEs and VCS streamline development, ensuring smooth workflows, better code management, and efficient debugging, ultimately improving software quality.

Explain the different types of testing (unit, integration, system, and acceptance) and their importance in software quality assurance.
Unit Testing – Focuses on testing individual methods, functions, or components to ensure each works as expected in isolation. This helps catch bugs early in development.
Integration Testing – Verifies that different modules or services interact correctly, ensuring smooth data flow and proper interface communication.
System Testing – Evaluates the entire software system to ensure it meets functional and non-functional requirements like performance, security, and usability.
Acceptance Testing – Conducted to validate whether the software meets business requirements and user expectations before deployment.

Define prompt engineering and discuss its importance in interacting with AI models.
Prompt Engineering is process where you guide AI generated results into a desired output its usefulness include;
Enhanced User Experience – Prompt engineering ensures users receive relevant results on the first attempt. It also helps reduce biases inherited from training data in large language models.
Greater Flexibility – Prompt engineers design domain-neutral prompts that emphasize logical connections and broad patterns, making them adaptable across various contexts.
Increased Developer Control – By crafting precise prompts, developers can shape user interactions with AI, providing clear intent and context to guide model responses effectively.
